# 《三国烽火》游戏设计文档

## 1. 游戏定位

《三国烽火》是一款以三国武将收集、同等级合成养成和固定点位塔防为核心的单机游戏。第一阶段优先验证可玩循环，不依赖在线服务、账号系统或服务器。

## 2. 核心循环

1. 进入游戏获得初始资源。
2. 消耗招募资源抽取武将，获得永久收藏中的武将副本。
3. 在武将界面查看副本、等级和属性。
4. 将同名且同等级的武将副本作为材料，合成提升目标副本等级。
5. 将武将部署到固定防守点位。
6. 开始战斗，武将自动攻击进入射程的敌人；玩家可以在战斗中手动更换点位上的武将。
7. 击败所有波次获得奖励；敌人抵达终点或防守目标生命归零则失败。
8. 使用奖励继续抽卡和养成。

## 3. 武将收集

武将类型与武将副本分离。HeroDefinition 表示武将模板，保存稳定 ID、名称、阵营、品质和基础战斗属性；HeroInstance 表示玩家持有的一份具体副本，拥有唯一副本 ID 和独立等级。

武将数量不设固定上限。新增武将通过数据配置完成，不应要求为每名武将复制一份战斗脚本。首批 50 名武将是原型数据，后续可持续添加。

阵营：魏、蜀、吴、群雄、晋。品质：普通、稀有、史诗、传说。具体概率、数值和成长曲线属于待平衡内容。

## 4. 三档抽卡与武将分级

抽卡只消耗战斗中击败敌人获得的金币。初始金币为 0，玩家使用初始武将进入战斗，击杀敌人后再购买卡池。每次抽卡生成新的独立武将副本并加入收藏。

| 卡池 | 单抽价格 | 可抽武将等级 | 各等级命中概率 |
|---|---:|---|---|
| 初级卡 | 20 金币 | 初级、中级 | 初级 75%，中级 25% |
| 中级卡 | 50 金币 | 初级、中级、高级 | 初级 55%，中级 30%，高级 15% |
| 高级卡 | 100 金币 | 中级、高级 | 中级 60%，高级 40% |

武将等级与品质的原型映射为：普通、稀有属于初级；史诗属于中级；传说属于高级。每名武将通过 `hero_catalog.json` 的 `tier` 字段显式声明等级，后续可单独调整，不应在业务代码中按名称硬编码。

概率按武将等级分组计算，再在该等级的所有可抽武将之间均分。因此新增某一等级的武将不会抬高该等级的总体命中率，只会改变该等级内部单个武将的概率。卡池权重集中配置在 `GachaService`，后续平衡时同步更新本文档和游戏内概率展示。

当前界面先展示卡池价格与可抽范围；正式发布前还应提供逐名武将的精确概率、抽卡记录，以及在设计需要时加入保底机制。

## 5. 同等级合成

默认规则：选择一个目标副本，消耗两个与目标同名、同等级的材料副本，目标等级提升 1 级。材料数量和等级上限通过服务构造参数控制。

- 目标副本不能被选作材料。
- 材料 ID 必须互不重复。
- 不允许消耗不存在的副本。
- 不允许跨武将或跨等级合成。
- 必须在所有校验通过后才修改收藏，避免部分消耗。
- 已上阵副本不应被合成消耗；战斗中禁止合成。UI/业务层需要统一执行此规则。

注意：目前该规则是原型默认值，若设计最终采用“目标 + 一个同等级材料”或其他数量，调整 HeroUpgradeService 的配置即可。

## 6. 固定点位与战斗

地图提供固定的防守点位，首期建议 5 个点位。一个武将副本同一时刻只能部署在一个点位。玩家可以在战前布阵，也可以在战斗中切换点位武将。

战斗原型包括：
- 敌人沿预设路径向终点移动。
- 武将自动寻找射程内目标并攻击。
- 敌人死亡提供战斗资源。
- 波次按配置生成，最后一波结束且敌人清空时胜利。
- 敌人到达终点会扣除基地生命。
- 基地生命归零则失败。

第一阶段采用简化的直线/路径原型，之后再换成关卡数据驱动的曲线路径、不同敌人和技能。

## 7. 局外成长与存档

本地保存软货币、已拥有武将副本、等级、布阵以及解锁进度。存档格式需带版本号，未来数据结构变化时可以迁移。原型阶段可先使用 JSON 文件，正式版本再评估加密、备份和防篡改需求。

## 8. 美术与音频原则

逻辑与美术分离。原型阶段用简单几何体、颜色、文字和占位图验证玩法；不将未经授权的三国人物图片、音乐或字体提交到仓库。后续替换素材时应确认授权许可。

## 9. 非目标

第一阶段不做联机 PvP、实时多人、服务端账号、复杂装备系统、开放世界或付费商城。先确保核心玩法循环稳定。
